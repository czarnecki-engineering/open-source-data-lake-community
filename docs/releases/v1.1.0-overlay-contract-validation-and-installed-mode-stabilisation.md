## 3. Architecture Contract

The validated branch state preserves the shared architecture contract in [`docs/architecture/overlay_contract_v1.md`](../architecture/overlay_contract_v1.md).

The contract conclusions carried into this release are:

- overlays are filesystem-first extensions applied to a standard installation root
- the standard contract surface remains `config/`, `dags/`, `notebooks/`, `scripts/`, `data/`, and `php/`
- overlays may be additive and composable, with later overlays overwriting earlier conflicting files
- runtime activation continues through the base start scripts with explicit overlay selection
- overlays must target explicit Airflow services `airflow-webserver` and `airflow-scheduler`
- the logical `airflow` service is not part of the contract
- Supported continues to require PostgreSQL for Airflow metadata
- file-based config-state remains a valid contract pattern where overlays require controlled writable configuration

The contract file was aligned cross-repo earlier in the validation sequence and remains the authoritative architectural baseline for this release.

## 10. False Negatives and Validation Discipline

Two important installed-mode failures previously reported in Community were reclassified as false negatives:

- `overlay_heartbeat_v2` installed mode
- `overlay_kaggle_ingestion` installed mode

The final evidence shows that those failures came from validation discipline issues rather than persistent branch defects:

- Airflow `/health` was sampled too early during scheduler-heartbeat startup, producing transient `unhealthy` results before steady state
- earlier Kaggle install findings were not reproduced from a clean install root on the current branch
- documentation ambiguity around archive contents and post-unzip paths contributed to incorrect failure interpretation

The release discipline carried forward from this work is:

- use clean `/tmp` install roots for installed-mode validation
- validate the actual archive contents being tested
- allow an appropriate 60 to 120 second Airflow warm-up before concluding scheduler failure
- distinguish runtime defects from documentation defects and from transient startup observations
