## Cross-Repo Findings

- Overlay parity: five overlays are present in both repos: `overlay_hello_world`, `overlay_heartbeat_v2`, `overlay_asx_historic_csv`, `overlay_kaggle_ingestion`, and `overlay_file_only_demo`. One overlay is Supported-only: `overlay_asx200_ohlcv_v2`. No Community-only overlays were reported.
- Packaging/install documentation risks: `overlay_heartbeat_v2` lacks a packaged compose overlay in both repos for installed mode, and `overlay_asx200_ohlcv_v2` in Supported lacks explicit archive build and unzip/install commands entirely.
- Command inconsistencies: `overlay_kaggle_ingestion` has conflicting archive commands in both repos, and Supported also documents the dev command as `./overlay_kaggle_ingestion/dev-start-compose.sh` while Community reports `bash overlay_kaggle_ingestion/dev-start-compose.sh`.
- Missing or mismatched config references: Community `overlay_asx_historic_csv` documentation references missing test config files; Supported `overlay_asx200_ohlcv_v2` requires mutable `config/asx200_ohlcv_jobs.json`; both repos report incomplete documentation of overlay-specific env inputs.
- PHP/UI path concerns: Supported `overlay_kaggle_ingestion/php/solutions/dataset_summary.php` declares a default summary path under `dirname(__DIR__) . '/data/...'` while the report separately records the compose-mounted PHP data path as `/app/data`.
- Contract concerns: both inventories repeatedly record explicit `airflow-webserver` and `airflow-scheduler` targeting instead of a purely abstract runtime contract; both report fallback credentials or base credential dependence on several overlays; both report undeclared env values across ASX, Kaggle, heartbeat, and hello world overlays; Community and Supported disagree in the inventory findings about whether some overlays reference logical `airflow`.
